# 项目接入

先读取项目已有 AGENTS、README、状态与验证规范，检查目录、已有改动、运行方式及权限。不要因默认文件名不同创建竞争来源。已有项目明确映射；新项目先建立五项基本职责，复制模板后填真实内容。模式选择与生效边界见 [lifecycle.md](lifecycle.md#模式与生效边界)。文档模式直接完成职责映射、内容核对和最小任务试用；下列配置和命令步骤适用于脚本模式。

1. 从脚本接口的 project.json 示例准备映射。确认来源可引用用户已授权范围；未决重大产品或验证边界仍保持候选。
2. 运行 adopt 预览，核对路径及 reused/created，再在授权内 --apply。脚本不覆盖已有文件；重复接入会复用已有配置，新映射不同会停止自动覆盖，由开发 AI 按已有授权比较并合并差异。
3. 填真实目标、验收、检查、环境和授权，在 README 中明确链接开发规则、需求、验证来源和状态入口。运行 doctor 处理占位符、缺文件及缺链接。doctor 不验证规则含义，由开发 AI 对照原始来源核对。
4. 创建接入任务记录，列产物路径、创建/复用/更新、内容状态、确认来源和实际检查。接入本身缺关键内容时写“文件已建立；项目接入未完成”。
5. 选最小实际任务试用，执行适用正反例及中断恢复。文件就绪与机制运行验证分别报告。

接入已有测试选择器、执行器、证据记录器或提交检查时，核对它们传递的输入范围、版本和结果含义，判定按 [verification.md](verification.md)。复用项目已有映射；不同工具需要转换时保留可追溯对应，不另立竞争清单。将适用衔接纳入上述实际任务试用，检查范围预览或等效记录与实际执行是否相符，并按风险验证异常结果能否传到交付检查；工具和实现方法由项目选择。

先复用已有等效说明：UX 标准存在内容缺口且需要独立维护时启用 UX 模板；产品规则复杂到需要独立维护时拆出 rules；任务和阶段计划按[任务流程](lifecycle.md)的依赖、检查点及风险条件启用；路线依赖未证实能力时使用实验记录；运行或数据说明复杂到需要独立维护时启用 development。原位置正文移动后修正引用，避免重复维护。单次发布记录写发布任务，CHANGELOG链接版本与任务，共用发布约定映射到AGENTS、验证来源和开发运行说明。模板索引列明文件名。

已有领域规范也纳入 README 的职责映射。新增对象适用的共同标准、验收依据及允许差异在原规范中明确；内容复杂到需独立维护时才分册并链接，不要求与模板逐一同名，也不把旧实现本身当成标准。

项目根目录不是 Skill 目录。传入 --root 后所有项目写入落在此目录；脚本拒绝外部路径和逃逸符号链接。命令仍以用户进程权限运行，项目规则不能作为操作系统沙箱。

升级先比较包版本与项目自身改动。配置没有自动迁移器；v1结构化任务使用 migrate-task 预览及显式应用，非结构化记录人工映射。读取新版本变更后在授权内合并并验证，不重新 adopt 覆盖配置。保留任务历史和原始证据。机制文件随项目保存，README 的接入说明记录 Skill 位置、版本和采用模式；版本不足以定位采纳内容时补来源提交或内容摘要，局部采纳或本地修改说明实际差异。跨机器时重新映射可读取位置。

空项目的检查映射不能引用尚不存在的源码或测试目录。先在已授权接入范围建立最小真实探针及其输入，或将接入检查映射到现有核心文件并实际核对其内容与引用；配置就绪后 begin 接入任务，再随实际源码补充检查映射。不用零测试、虚构计数或空文件证明产品功能通过。接入阶段的文件建立事实与功能开发验收分开。

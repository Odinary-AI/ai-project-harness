# 项目目录与文件归属

本文件维护默认布局、采用选择和文件归属规则；项目 README 记录实际采用的位置与例外，不复制另一套通用规则。复杂目录说明移至已有 architecture 或 development，README 保留链接。目录统一服务于定位与维护，不要求预建空目录。

## 采用与迁移

- 新项目且无既定布局，默认采用下表，按实际工作创建需要的目录。只有文档或单文件产物的项目不必建立 src、tests 等无用目录。
- 已有项目首次接入，先核对现有结构、框架要求及用户已有决定，说明保留并映射与迁移到默认布局的影响，由用户选择；已有明确选择直接复用。首次治理不等于新项目；等待选择时可以调查，不移动文件。
- 框架或工具要求的 app、public、apps、packages 等布局优先适配，在项目导航中映射到对应职责；不再建立职责相同的默认目录。根目录的工具配置及依赖锁文件保留其要求位置，测试可按框架约定与源码相邻。
- 选择迁移时，先给出原路径到新路径、消费者/命令/配置/导入/链接的修改、受影响验证及恢复办法，再按用户已选范围执行。保留历史证据，检查相关指纹失效，不把旧通过状态当迁移通过。超出已选范围或涉及难以恢复的数据操作时另行确认。

## 默认归属

下表是职责到位置的默认映射，不是必须一次创建的清单。已有项目可以保留映射；脚本模式的固定存储位置仍以[脚本接口](cli.md)为准。

| 默认位置 | 用途与边界 | 创建与提交 |
|---|---|---|
| README.md | 项目入口、基本启动说明、实际目录导航与采用选择 | 基本职责，通常提交 |
| AGENTS.md | AI执行规则、授权和项目约束 | 基本职责，通常提交 |
| TESTING.md | 验证范围、环境、命令和证据要求 | 基本职责，通常提交 |
| CHANGELOG.md | 用户可见版本变化与发布任务索引 | 有版本维护需要时建立，通常提交 |
| .gitignore | 临时文件、生成物、秘密及项目例外的忽略规则 | 使用Git时按实际内容维护；忽略规则不等于已跟踪内容自动移除 |
| .env.example | 环境变量名称及无秘密示例 | 需要时建立，提交示例；真实秘密不提交 |
| 根目录工具配置、依赖清单与锁文件 | 技术栈要求的构建/依赖配置 | 按工具要求放置；适用锁文件通常提交 |
| src/ | 产品源码及按模块组织的运行逻辑 | 需要时建立，提交；框架指定结构可映射替代 |
| tests/、tests/fixtures/ | 测试代码及专用样本 | 需要时建立，通常提交；敏感/大型样本采用安全替代或外部来源 |
| config/ | 应用运行配置，不重复根目录工具配置 | 按需，提交无秘密的默认/示例配置 |
| scripts/ | 开发、构建、检查、迁移等辅助工具 | 按需，通常提交；产品业务逻辑归源码 |
| assets/ | 产品静态源资源 | 按需，通常提交；与public或模块内资源按用途映射，不复制 |
| docs/requirements.md | 目标、范围、需求与验收 | 基本职责，通常提交 |
| docs/status.md | 当前工作入口、交接与少量后续待办 | 基本职责，通常提交；详细执行状态归任务 |
| docs/tasks/TASK-001.md | 任务执行、简单计划/决定/实验和单次发布记录 | 有任务时创建；沿[任务流程](lifecycle.md)维护 |
| docs/architecture.md、rules.md、ux-guidelines.md、glossary.md | 架构、产品规则、UX及术语的独立正文 | 仅相应内容需要独立维护时建立，通常提交 |
| docs/development.md | 复杂环境、部署、运行日志和恢复说明 | 简单内容先放README；拆分后原处改链接 |
| docs/backlog.md | 较多、需要排序和长期跟踪的后续事项 | 少量待办先放status；拆分后status保留入口 |
| docs/plans/、decisions/、experiments/ | 复杂或跨任务复用的计划、决定与实验记录 | 默认先放任务；需要独立维护才拆，任务引用正文，不重复维护 |
| docs/evidence/任务对应目录/ | 扫描报告、审阅、截图等任务证据附件 | 按需保存可复核材料；脱敏后按保留要求提交，不复制已有RUN日志 |
| data/ | 产品运行或研究数据 | 按需；默认不提交数据内容，必要可版本化样本明确例外；测试专用样本归fixtures |
| logs/ | 产品运行日志 | 按需；默认忽略，保留/清理遵循运行要求；不能当临时文件任意删除 |
| dist/ | 构建与打包产物 | 按需；默认忽略，需要版本化的交付物明确例外 |
| tmp/ | 可丢弃的临时文件 | 按需；默认忽略，不承载唯一有效证据或不可恢复数据 |
| .harness/ | 脚本配置、任务验证RUN和交付回执 | 仅脚本模式；持久配置/证据与锁、会话临时状态分开处理，不整体忽略 |
| .codex/hooks.json | 选择Codex事件适配时的本机配置 | 按[适配约定](codex-hooks.md)生成和审阅，不当通用可移植配置 |

目录组合可随需求增长；不因为表中存在条目就创建文件。没有Git时仍遵守归属、秘密保护与保留边界。小项目合并的是承载位置，不省略需求、验证、实验依据或必要交接内容。没有总plan或releases的默认文件；既有有效来源可以复用。

## 目录检查与清理入口

用户要求检查目录、多余文件或整理清理项目时，从本入口沿现有布局开展有界任务，不必先做完整项目治理。显式加载使用 `$ai-sdlc`；已采纳项目规则的生效边界仍按[lifecycle.md](lifecycle.md)。只要求检查时交付发现；已授权清理时主动完成范围内可确认的处置，不等待用户逐个指出文件。咨询不创建实施任务，现有任务与保留要求按原流程维护。

1. **主动调查候选。** 核对项目入口、已有修改、实际目录及生成/归档关系，覆盖所要求范围内的已跟踪、未跟踪与被忽略对象；不能只判断目录命名是否合理。按线索检查缓存、空目录、临时副本、已被正式记录覆盖的中间输入/结果、归档与展开副本等；这些是候选而非必删清单，不凭名称、任务完成或Git忽略状态认定无用。范围大时按风险深入，说明未覆盖部分，不把抽样结论扩成全项目无冗余。
2. **判断可删、保留或待核实。** 结合当前读取者、生成来源、项目保留约定及恢复需要判断，复用[证据保留边界](verification.md#执行证据与交付)和[否定结论取证](maintenance.md#结果底线与方法选择)。区分当前有效消费者、历史路径记载与仍有要求的复现工具；存在引用不等于必须永久保留，搜不到引用也不足以删除。对归档副本核对覆盖及内容完整性，对结果副本核对正式记录是否已包含其有用信息；存在唯一失败、恢复或审计信息时保留。缓存确认可再生成，空目录确认无工具或运行约定依赖。
3. **推进处置而非仅列疑点。** 对影响可删判断的疑点，先用授权内低成本检查补证据；仍无法确定时说明缺什么、暂留原因及下次动作/触发，不把“有引用”当最终结论。若解除依赖需改造历史复现工具、迁移唯一材料或改变保留规则，按原授权判断；超出范围先报告，不为清空目录扩展任务。明确清理请求下，可确认对象继续处理，待核实对象不阻塞独立可删项；已有授权不重复申请，原有保留决定不会因泛化清理请求自动失效。
4. **执行与交接。** 删除前固定实际对象及应保留内容，确认相应恢复来源；保护用户及其他任务改动，不跟随链接删除范围外内容。按下文比例验证核对实际删除、保留对象、有效消费者与必要文档同步。记录可复核的清理范围、结果及恢复依据，批量对象按需附清单；待核实项给出下一动作，保留项说明必要理由。收尾区分本次清理完成与仍待判断部分，不宣称已消除全项目冗余。只读任务交付分类发现即可，不生成删除动作；不另建治理台账或默认全量测试。

## 日常维护与健康检查

新建文件前确认现有归属，不在根目录随意堆放，不新增同义目录。新增顶层目录、职责拆分或迁移时说明必要性并更新项目导航；拆出独立正文后旧位置保留引用。一般授权内的可逆安排不需要逐文件批准，不能由此覆盖已有项目的迁移选择。

健康扫描按项目已采用的布局检查错放文件、重复职责、孤立文件、临时/生成物混入源码、秘密或大型数据误提交、移动后的导入/命令/链接及证据失效。缺依据先追查消费者，不以未检索到引用就删除。框架差异和已记录例外不是缺陷；扫描本身不授权迁移或清理。发现、处置与验证沿maintenance和现有任务记录，不另建目录治理台账。

目录整理的验证按实际操作选择：已有Git基线、仅修改文档且没有移动文件时，优先核对基线、暂存与工作树差异及保护路径，不默认遍历全库计算散列；同时检查本次涉及的未跟踪或被忽略对象，Git差异不能证明它们未变。迁移、归档或未跟踪的重要文件按完整性与恢复要求核对内容，必要时逐文件比较或计算散列。明确可再生成的缓存通常保留清理范围与结果即可；需要回退时记录恢复位置，不默认逐文件留存散列。相关命令、链接及证据有效性检查仍按受影响范围执行。

维护：默认规则变化先更新本文件及入口；项目实际布局变化只更新其唯一导航/说明与消费者。adopt只创建其既有核心文件，不自动创建所有目录、移动已有文件或生成完整.gitignore；上述选择与检查由开发AI执行并留证。
